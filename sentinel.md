# Microsoft Sentinel

## Overview

Microsoft Sentinel is the primary cloud-native SIEM used in this project to collect, analyze, detect, investigate, and respond to security events.

In this SOC lab, Sentinel acts as one of the central security monitoring platforms. Security telemetry generated by the Windows endpoint, Sysmon, and Microsoft Entra ID is collected into Microsoft Sentinel and analyzed using Kusto Query Language (KQL).

The objective is to build realistic SOC detection and investigation workflows rather than simply collecting logs.

---

## What We Are Doing With Microsoft Sentinel

The Sentinel portion of this project focuses on the complete security monitoring lifecycle:

1. Collect security logs from lab systems.
2. Ingest the logs into Microsoft Sentinel.
3. Understand and normalize the available security data.
4. Create KQL-based detection queries.
5. Convert important detections into Analytics Rules.
6. Generate alerts and incidents from suspicious activity.
7. Investigate incidents using KQL and Sentinel investigation features.
8. Perform threat hunting across historical telemetry.
9. Map detected activity to MITRE ATT&CK techniques.
10. Use automation and playbooks for controlled response actions.
11. Provide relevant information to the Python/AI investigation layer.

## Data Sources

The project will use multiple security telemetry sources, including:

### Windows Security Events

Windows Security logs provide authentication, account, privilege, and other security-related events.

Examples include:

- Successful logons
- Failed logons
- Account activity
- Privilege-related events
- Security policy changes

### Sysmon

Sysmon provides detailed endpoint telemetry that can help investigate suspicious processes and system activity.

Examples include:

- Process creation
- Network connections
- File activity
- Process relationships
- PowerShell execution

### Microsoft Entra ID

Entra ID provides identity and authentication telemetry that can be used to investigate suspicious account activity.

Examples include:

- Sign-in activity
- Failed authentication
- Successful authentication
- Authentication-related errors
- Suspicious login patterns

## Detection Scenarios

The Sentinel environment will be used to detect and investigate several controlled attack scenarios within the lab.

### 1. Password Spraying / Brute Force

Detect repeated authentication failures and identify suspicious authentication patterns such as:

- Multiple failed logins
- One source attempting multiple accounts
- Failed logins followed by a successful login

### 2. Suspicious PowerShell Activity

Detect potentially suspicious PowerShell execution using endpoint telemetry.

The investigation will examine:

- User
- Host
- Parent process
- Command line
- Process creation time
- Related network activity

### 3. Privilege Escalation

Monitor suspicious changes involving privileged accounts or groups.

The investigation will determine:

- Who performed the action
- Which account was affected
- Which privilege or group changed
- When the change occurred
- What activity followed it

### 4. Lateral Movement

Correlate authentication and endpoint activity to identify suspicious movement between lab systems.
